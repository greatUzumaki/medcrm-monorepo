# Реагирование на инциденты с ПДн

> Шаблон. Ответственных, контакты и формулировки уведомлений заполняет руководство и юрист. Проверять раз в квартал учебным прогоном.

## Сроки (ст. 21 ч. 3.1 152-ФЗ)
- **24 часа** с момента выявления — первичное уведомление РКН: что произошло, предполагаемые причины, вред, принятые меры, контактное лицо.
- **72 часа** — результаты внутреннего расследования и лица, причастные к инциденту (если установлены).
- Взаимодействие с ГосСОПКА — по требованиям, применимым к оператору.

## Шаги
1. **Зафиксировать** время выявления, источник сигнала. Завести тикет инцидента (без ПДн в описании).
2. **Сдержать**: отозвать скомпрометированные сессии/ключи/токены интеграций, заблокировать учётку, закрыть уязвимый эндпоинт feature-флагом, при необходимости — режим только-чтение.
3. **Сохранить доказательства**: снимок `audit_log`, access-логов, трейсов за период; не перезаписывать.
4. **Оценить масштаб** — запросы к `audit_log`: какие пользователи, какие пациенты, какие клиники, какие поля (классы S/P), объём экспорта.
5. **Уведомить** РКН (24ч), затем клиники-операторы и, при необходимости, субъектов.
6. **Устранить** причину, ротировать ключи (`crypto` key version++ + перешифровка), выпустить фикс.
7. **Расследование и отчёт** (72ч): хронология, причина, затронутые данные, меры.
8. **Постмортем** без поиска виноватых: что добавить в тесты/алерты/скиллы Claude.

## Технические сигналы (алерты)
- аномальный объём чтения карт/экспорта одним пользователем
- массовые 403/404 на объектах (перебор id)
- вход с нового ASN/страны, множественные неудачные входы
- срабатывание gitleaks/секрета в логах
- всплеск 5xx на auth / изменение RLS-политик / новая роль с BYPASSRLS

# ПДн и врачебная тайна: требования → код

> Это инженерный чек-лист, не юридическое заключение. Нормы меняются — финальные решения (уровень защищённости, тексты согласий, уведомления в РКН, выбор СКЗИ) за юристом/ответственным за ПДн. Если правило ниже противоречит задаче — остановиться и спросить, а не обходить.

## Классификация данных (указывать в плане фичи)
| Класс | Примеры | Обращение |
|---|---|---|
| **S — спецкатегория / врачебная тайна** | диагнозы, жалобы, анамнез, назначения, результаты анализов, факт обращения в клинику, аудио приёма | шифрование, аудит чтения, строгий RBAC, ИИ только in-perimeter или после редакции |
| **P — идентифицирующие ПДн** | ФИО, ДР, телефон, email, адрес, паспорт, СНИЛС, полис | паспорт/СНИЛС/полис — шифрование + blind index; маскирование в UI (`***-***-789 01`) |
| **I — внутренние** | id, статусы, суммы без привязки | обычные |
Даже связка «пациент X был у гинеколога» — это S. Сам факт обращения — врачебная тайна.

## 1. Законность и согласие (152-ФЗ ст. 6, 9, 10; 323-ФЗ ст. 13, 20)
- Каждое поле ПДн имеет **цель** (в `docs/pdn/registry.md`: поле → цель → основание → срок). Новое поле без цели не добавлять.
- Согласие на обработку ПДн — **отдельный документ**, не внутри договора/оферты, не предзаполненный чекбокс. Хранить: версия текста, дата/время, способ, кто принял (`consents` таблица, неизменяемая, append-only).
- Отзыв согласия — функциональность в CRM, запускает процедуру прекращения обработки/уничтожения (с учётом обязательных сроков хранения медицинской документации).
- Передача третьим лицам (лаборатории, страховые, SMS-шлюз, LLM-провайдер) — только при наличии основания; поручение обработки фиксируется договором. В коде: интеграция не стартует без флага `legal_basis_confirmed` в конфиге клиники.

## 2. Локализация и трансграничка (ст. 18 ч. 5, ст. 12)
- Первичная запись, хранение, бэкапы, реплики, логи, объектное хранилище, очереди — **на серверах в РФ**.
- Внешние SaaS (Sentry, аналитика, LLM, почта, CDN для приватных файлов) — только РФ-размещение либо без ПДн вообще. Добавление нового внешнего сервиса = вопрос пользователю.
- Трансграничная передача требует уведомления РКН — по умолчанию её **нет** в архитектуре.

## 3. Защита (ст. 19, ПП РФ № 1119, приказ ФСТЭК № 21)
Уровень защищённости определяет юрист; в коде закладываем меры, достаточные для высокого уровня:
- **Идентификация и аутентификация**: персонал — пароль (argon2id) + TOTP обязательно для ролей с доступом к S; блокировка после N неудач; сессии с idle-timeout (30 мин) и абсолютным (12 ч); выход везде при смене пароля.
- **Управление доступом**: RBAC + принцип минимальных привилегий; врач видит своих пациентов/отделение, доступ «вне потока» (break-glass) — с указанием причины и отдельным аудитом.
- **Регистрация событий**: `audit_log` append-only (нет UPDATE/DELETE у роли `app`), хранение ≥ срока, требуемого политикой; события: вход/выход/неудачи, чтение S, изменение, экспорт, печать, смена прав, выгрузки.
- **Криптозащита**: TLS везде, включая внутри периметра (API ↔ БД). Шифрование полей/бэкапов. Необходимость сертифицированных СКЗИ (ГОСТ) на каналах — решение юриста по уровню защищённости; архитектура должна позволять поставить ГОСТ-TLS терминатор перед сервисом без изменения кода.
- **Целостность и доступность**: бэкапы зашифрованы, тест восстановления регулярно, RPO/RTO задокументированы.
- **Контроль уязвимостей**: govulncheck, gosec, npm audit, сканирование образов в CI; обновления зависимостей.

## 4. Минимизация и отображение
- API отдаёт только поля, нужные конкретному экрану. Списки — без S-полей.
- Маскирование идентификаторов в UI по умолчанию, «показать» → аудит.
- Экспорт (CSV/PDF/печать) — отдельное право, водяной знак с пользователем и временем, аудит, лимит объёма.
- Поиск пациента — по точному совпадению/префиксу через blind index, без «выгрузи всех».

## 5. Сроки и уничтожение (ст. 5 ч. 7, ст. 21)
- Сроки хранения по каждой сущности в `docs/pdn/registry.md` (медицинская документация хранится по требованиям Минздрава — дольше, чем «пока нужно»).
- River-джоба `retention` уничтожает/обезличивает по истечении срока; формирует **акт уничтожения** (запись в `destruction_log` + выгрузка) — формат по требованиям РКН.
- Удаление = крипто-удаление где возможно (уничтожение ключа записи) + удаление из бэкапов по ротации.
- Обезличивание для аналитики/обучения моделей — только необратимое, отдельным процессом, с согласованием.

## 6. Права субъекта (ст. 14, 20, 21)
Эндпоинты/функции для ответственного: «какие данные о пациенте есть и кому передавались» (выгрузка из `audit_log` + реестра передач), уточнение, блокирование, прекращение обработки. Срок ответа ограничен законом (рабочие дни) — в CRM задача с дедлайном и напоминанием.

## 7. Инциденты (ст. 21 ч. 3.1)
- При утечке — уведомление РКН в **24 часа** (первичное) и **72 часа** (результаты расследования). Поэтому код обязан давать ответ «что утекло и чьё»:
  - аудит позволяет восстановить, кто и какие записи читал/выгружал за период;
  - алерты: аномальный объём чтения/экспорта одним пользователем, массовые 403/404, вход из новой страны, всплеск 5xx на auth.
- Runbook: `docs/security/incident-response.md` (ответственные, контакты, шаги, шаблоны уведомлений). При изменениях логирования/аудита — проверить, что runbook остаётся выполнимым.
- За утечки ПДн, особенно спецкатегорий, предусмотрены крупные (в т.ч. оборотные) штрафы и уголовная ответственность — это не «потом поправим».

## 8. Разработка
- Реальные ПДн **никогда** в: репо, тестах, фикстурах, seed, скриншотах, баг-репортах, промптах Claude/других LLM, Slack/Telegram. Отладка на проде — через обезличенные дампы.
- Стенды dev/stage — только синтетика. Копия прода на stage запрещена.
- Feature flag для новых интеграций с передачей ПДн выключен по умолчанию.

## Чек-лист изменения с ПДн
- [ ] класс данных (S/P/I) каждого нового поля определён, цель записана в реестр
- [ ] основание обработки есть (согласие/договор/закон), для новых получателей — подтверждено пользователем
- [ ] хранение в РФ, нет новых внешних получателей без согласования
- [ ] S/P-идентификаторы зашифрованы, поиск через blind index
- [ ] RBAC + аудит чтения и изменения, экспорт отдельным правом
- [ ] нет ПДн в логах/трейсах/метриках/URL/ошибках/клиентском хранилище
- [ ] срок хранения и способ уничтожения определены
- [ ] агент `phi-guard` прогнан
